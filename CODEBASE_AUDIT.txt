9. CRITICAL AUDIT FINDINGS & SCHEMA MISMATCHES
================================================================================

✅ STRENGTHS:
1. Full type safety with src/types/database.ts
2. Robust CORS with strict origin validation
3. Async resilience (observationInsert.ts error handling)
4. RLS enforcement on all user-scoped tables
5. Versioned compliance rules (zone_compliance_matrix with effective_from/effective_to)
6. Adaptive observation insert (retry with column omission on schema cache misses)

⚠️ KNOWN DRIFT ISSUES (Fixed by migrations):
1. COALESCE Type Mismatches (20260312, 20260313, 20260401)
   - Triggers expect INTEGER, columns are TEXT
   - Solution: Type casting in trigger COALESCE, omit fields on error

2. Column Name Drifts
   - latitude/longitude → gps_latitude/gps_longitude
   - full_name → first_name + last_name
   - Solution: Type corrections in database.ts

3. Schema Cache Delays (20260312, 20260315)
   - New columns not immediately visible
   - Solution: Refresh cache, retry with column omission

4. Vehicle Record Split (20250203, 20250127)
   - Legacy: single vehicle_records
   - Current: canonical_vehicles + observations (denormalized)
   - Solution: Bidirectional syncs

5. Breach Type Constraints (20260217, 20260331)
   - CHECK constraint on breach_alerts.breach_type
   - Valid types: consecutive_nights, monthly_limit, self_contained, after_hours, day_visit_violation, allowed_days_violation
   - Solution: toValidBreachType() from compliance.ts

6. RLS Enforcement Iterations (20260218, 20260227, 20260307, 20260314)
   - Service role needed explicit storage access
   - Officer RLS too restrictive initially
   - Solution: Multiple RLS policy refinements

7. Homeless Exemption Alignment (20260310)
   - Flag on canonical_vehicles, exemption logic in compliance_results
   - Solution: is_homeless_exempt field in compliance_results

8. Overnight Verification Mode (20260309, 20260225)
   - Organizations support: 'two_photo_verification' | 'one_photo_per_day_inference'
   - Compliance logic varies by org mode
   - Solution: Mode read from organizations table in recalculation

9. Zone Compliance Matrix Versioning (20260301, 20260322)
   - Multiple effective_from/effective_to dates per zone
   - Solution: Version selection by date in compliance engine

10. Observations Idempotency (20260330)
    - Duplicate prevention via idempotency_key
    - Solution: Unique constraint on (plate_number, zone_id, recorded_at, idempotency_key)

10. DATA FLOW DIAGRAMS
================================================================================

VEHICLE SCAN FLOW:
1. vehicle-ingest receives photo + metadata
   → Validates GPS (15m threshold)
   → Calls alprWithBytes() (from _shared/alpr.ts)
   → Inserts observation with adaptive error handling
2. Database trigger on observations INSERT
   → Calls evaluate_compliance_v4() function
   → Creates/updates compliance_results
   → Evaluates against zone_compliance_matrix (date-versioned)
3. scan-breaches (async or scheduled)
   → Queries compliance_results.is_compliant = false
   → Creates breach_alerts for each non-compliant observation
4. check-almost-breaches (hourly scheduled)
   → Early warning for near-breach vehicles
   → Sends push notifications

COMPLIANCE RECALCULATION FLOW:
1. Admin triggers recalculate-compliance-v3 with zone/date/org filters
2. Function queries observations by filters
3. For each observation:
   → Look up vehicle in canonical_vehicles
   → Check homeless exemption and flagged support
   → Evaluate against zone_compliance_matrix (effective at recorded_at)
   → Apply organizations.overnight_verification_mode
   → Store result in compliance_results
4. Sync results to observations.compliance_summary (JSON)
5. Auto-generate breach alerts from non-compliant results

ALPR INTEGRATION FLOW:
1. vehicle-ingest → calls alprWithBytes() from _shared/alpr.ts
2. Uses PLATERECOGNIZER_TOKEN (canonical) or PLATE_RECOGNIZER_TOKEN (legacy)
3. Returns { plate, confidence, raw }
4. Fallback to manual entry if confidence < threshold

PARKPOW INTEGRATION FLOW:
1. parkpow-sync uses parkpow.ts helper
2. Checks PARKPOW_API_TOKEN
3. Syncs watchlists (flagged plates) and permits (allowed plates)
4. Results may exempt vehicles from certain breaches
